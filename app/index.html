Understanding CI vs. CD

Continuous Integration (CI)

Validation & Verification

Continuous Integration is the practice of automatically integrating code changes from multiple contributors into a shared repository several times a day.

  • Runs on every Pull Request and branch commit.
  • Executes linters, syntax checks, and unit tests.
  • Builds ephemeral containers to run automated smoke tests.
  • Outcome: Immediate feedback on regressions before code is merged.

Continuous Delivery (CD)

Artifact Release

Continuous Delivery ensures that verified code changes can be safely and reliably released at any time.

  • Runs strictly on protected branches (e.g., main) or version tags.
  • Packages immutable, production-ready container images.
  • Publishes versioned artifacts to GitHub Container Registry (GHCR).
  • Outcome: An audited, signed container image ready for deployment.

Pulling the Container Image

Published images from this workflow can be retrieved from GitHub Container Registry:

bash 
# Pull the latest release
docker pull ghcr.io/OWNER/docker-cicd-pipeline:latest

# Or pull a specific semantic version / commit SHA
docker pull ghcr.io/OWNER/docker-cicd-pipeline:v1.0.0
docker pull ghcr.io/OWNER/docker-cicd-pipeline:sha-$(git rev-parse --short HEAD)

# Run container locally on port 8080
docker run -d --name cicd-app -p 8080:8080 --read-only ghcr.io/OWNER/docker-cicd-pipeline:latest
